# T5.6 — Əlçatanlıq

| | |
|---|---|
| **Prioritet** | P1 |
| **Təxmin** | 1,5 gün |
| **Asılılıq** | T3.4 (mətnlər resources-da olmalıdır) |
| **Branch** | `a11y/duymeler-ve-hedefler` |

## Problem

Kodda **sıfır** `Role` və sıfır `semantics` modifikatoru var. Bütün düymələr
`Text(...).clickable { }` ilə qurulub:

```kotlin
// CodeCard.kt:193 — KodDuymesi
Row(Modifier.border(...).clickable(onClick).padding(horizontal = 8.dp, vertical = 5.dp))
```

İki nəticə:

1. **TalkBack** bu elementləri «düymə» kimi oxumur — sadəcə mətn eşidilir,
   istifadəçi onun toxunula bilən olduğunu bilmir.
2. **Toxunma hədəfi kiçikdir.** Material minimumu 48 dp; `Modifier.clickable`
   isə (Material `Button`-dan fərqli olaraq) heç bir minimum tətbiq etmir:

| Komponent | Təxmini hündürlük |
|---|---|
| `KodDuymesi` (CodeCard) | ≈ 25 dp |
| `SeviyyeCipi` (çalışmalar) | ≈ 27 dp |
| `DemoChip` | ≈ 28 dp |
| `KicikDuyme` (çalışmalar) | ≈ 33 dp |
| `TeklifCipi` (redaktor) | ≈ 25 dp |

## Həll

### 1. Ortaq komponent

Təkrarlanan `Text + clickable` nümunəsini bir yerə yığ:

```kotlin
// ui/components/KAzDuyme.kt
@Composable
fun KAzDuyme(
    etiket: String,
    onClick: () -> Unit,
    modifier: Modifier = Modifier,
    vurgulu: Boolean = false,
    aktiv: Boolean = true
) {
    Text(
        text = etiket,
        modifier = modifier
            .clip(...)
            .background(...)
            .minimumInteractiveComponentSize()          // ← 48 dp qarantiyası
            .clickable(
                enabled = aktiv,
                role = Role.Button,                      // ← TalkBack üçün
                onClick = onClick
            )
            .padding(...),
        …
    )
}
```

`minimumInteractiveComponentSize()` görünən ölçünü dəyişmir — yalnız toxunma
sahəsini genişləndirir, ona görə dizayn pozulmur.

### 2. Tətbiq yerləri

`KodDuymesi`, `KicikDuyme`, `SeviyyeCipi`, `DemoChip`, `TeklifCipi`,
`Secim` (Tənzimləmələr), `Sifirla`, `AddimDuymesi`, «Yoxla», «İşlə»,
«Növbəti sual», rejim seçiciləri, alt menyu (`NavigationBarItem` onsuz da düzgündür).

### 3. contentDescription auditi

- **Dekorativ** ikonlar (kart nişanları, ✓ göstəriciləri): `null`
- **Mənalı** ikonlar (geri, axtarış, tənzimləmə, kopyala, bookmark):
  `stringResource(...)` — hazırda bəziləri azərbaycanca hardcoded-dır
- **Tərəqqi zolaqları:** `Modifier.semantics { contentDescription = "…" }`
  ilə faizi səslə oxunan et
- **Quiz variantları:** düzgün/səhv vəziyyəti yalnız rənglə göstərilir —
  `stateDescription` əlavə et («düzgün cavab», «səhv cavab»)

### 4. Rəng kontrastı

Tənzimləmələrdəki `textFaint` (açıq temada `#8A8A9E`, fon `#FFFFFF`) —
kontrast ≈ 3.4:1, WCAG AA (4.5:1) altındadır. Kiçik yazılarda işlədilən
yerləri yoxla və `textDim`-ə keçir.

## Yoxlama

- **Accessibility Scanner** (Play Store) — 5 əsas ekran
- **TalkBack** ilə əl ilə: dərs, çalışma, test, meydan, tənzimləmə
- Android Studio Layout Inspector → toxunma hədəfləri

## Qəbul kriteriyası

- [ ] Accessibility Scanner-də «touch target» xəbərdarlığı yoxdur
- [ ] TalkBack hər interaktiv elementi «düymə» kimi oxuyur
- [ ] Bütün mənalı ikonların tərcümə edilmiş `contentDescription`-ı var
- [ ] Dekorativ ikonlarda `contentDescription = null`
- [ ] Quiz variantının vəziyyəti səslə bildirilir
- [ ] Kontrast problemləri düzəldilib (və ya baseline-a yazılıb)
- [ ] Görünən dizayn dəyişməyib (screenshot müqayisəsi)

## Diqqət

`minimumInteractiveComponentSize()` sıx yerləşmiş çipləri **bir-birinin
üstünə salmır**, amma `Arrangement.spacedBy(6.dp)` ilə birlikdə sıra
hündürlüyünü artıra bilər. Redaktorun təklif zolağında bunu yoxla — zolaq
kodun üstündədir və yer darıdır.

# T2.4 — Qalan UI state-in bərpası və configChanges

| | |
|---|---|
| **Prioritet** | P0 |
| **Təxmin** | 1 gün |
| **Asılılıq** | T2.2, T2.3 |
| **Branch** | `fix/process-death` |

## Problem

Kodda **sıfır** `rememberSaveable` və sıfır `SavedStateHandle` var
(T2.2/T2.3-dən sonra ikisi əlavə olunur). Qalan itən state:

| Ekran | İtən |
|---|---|
| Çalışmalar | rejim (nəzəri/praktiki), səviyyə filtri, cari indeks |
| Dərs | `TabsView` seçili tab |
| Axtarış | sorğu mətni |
| Kod kartı | açılmış «Nəticə» paneli |
| Tənzimləmələr | açıq təsdiq dialoqu |
| Çalışma | açıq «Cavaba baxmaq istəyirsən?» dialoqu |

Manifestdəki (`AndroidManifest.xml:21`):

```xml
android:configChanges="orientation|screenSize|screenLayout|keyboardHidden|uiMode"
```

yalnız konfiqurasiya dəyişikliyində Activity-nin yenidən yaradılmasını **gizlədir**.
Arxa planda öldürülən prosesə heç bir təsiri yoxdur, üstəlik Compose-da lazım
deyil və gələcəkdə resurs yenilənməsini (dil dəyişməsi — T3.3!) poza bilər.

## Addımlar

1. Yuxarıdakı state-ləri `rememberSaveable`-a keçir:

```kotlin
var rejim by rememberSaveable(topic.id) { mutableStateOf(Rejim.NEZERI) }
var index by rememberSaveable(topic.id) { mutableIntStateOf(0) }
var seviyye by rememberSaveable(topic.id, stateSaver = …) { mutableStateOf<Level?>(null) }
```

`Level?` və `Rejim` enum-ları üçün ya `Saver` yaz, ya da `String`/`Int` kimi saxla
(ən sadə: enum `name`-i saxla, geri oxuyanda `entries.firstOrNull { it.name == s }`).

2. `configChanges` sətrini manifestdən **tamamilə sil**.

3. Sınaq ssenarisi (əl ilə və ya skript):

```bash
adb shell settings put global always_finish_activities 1   # Don't keep activities
# hər ekranda: state qur → home → geri qayıt → yoxla
adb shell am kill az.kotlinaz.app                           # process death
adb shell settings put global always_finish_activities 0
```

## Qəbul kriteriyası

- [ ] Manifestdə `configChanges` yoxdur
- [ ] Cədvəldəki 6 state döndərmədən sonra qalır
- [ ] Process death-dən sonra da qalır
- [ ] Klaviatura açıq ikən döndərmə redaktoru pozmur (IME davranışı əvvəlki kimi)
- [ ] Dərs ekranında sürüşmə mövqeyi qalır (`rememberLazyListState` onsuz da saveable)

## Diqqət

`rememberSaveable` Bundle-a yazır — **böyük mətn qoyma**. Redaktor kodu
(bəzən kilobaytlarla) `SavedStateHandle`-dadır (T2.2), `rememberSaveable`-da yox;
Bundle limiti (~1 MB, TransactionTooLargeException) belə aşılmır.

`configChanges` silinəndən sonra döndərmədə Activity yenidən yaranır — bu
**gözləniləndir**. Əgər nəsə itirsə, həmin state hələ də `remember`-dədir,
`rememberSaveable`-a keçirilməlidir.

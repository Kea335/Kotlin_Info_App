|---|---|

## Problem

`AppViewModel` (219 sətir) bütün tətbiqin məsuliyyətini daşıyır: aktiv yükləmə,
tənzimləmələr, tərəqqi, kompilyator, axtarış indeksi, meydana kod ötürülməsi.

`AppRoot` kökdə 14 StateFlow toplayır:

```kotlin
val hazir by vm.hazir.collectAsStateWithLifecycle()
val sections by vm.sections.collectAsStateWithLifecycle()
… // 12 dənə də
```

və hamısını parametr kimi ekranlara paylayır. Nəticə: istənilən dəyişiklik
(məsələn bir çalışmanın həll edilməsi) naviqasiya kökünü yenidən qurur, ekranlar
isə müstəqil test edilə bilmir.

## Həll

| ViewModel | Məsuliyyət | Mənbə |
|---|---|---|
| `AppViewModel` | aktiv yükləmə, `hazir`, `yukleneXetasi`, `tereqqi`, meydana ötürülən kod | qalır |
| `LessonsViewModel` | bölmə siyahısı, qruplar, son bölmə, «oxundu» yazılması | yeni |
| `SearchViewModel` | `AxtarisMotoru`, sorğu state-i, nəticələr | yeni |
| `SettingsViewModel` | tema, şrift, tamamlama, sıfırlamalar, rekordlar | yeni |
| `ExerciseViewModel` | T2.2-dən | var |
| `PlaygroundViewModel` | T2.2-dən | var |
| `QuizViewModel` | T2.3-dən | var |

`AppRoot`-dakı `collectAsStateWithLifecycle` çağırışları ekranların özünə keçir;
kökdə yalnız `hazir`, `yukleneXetasi` və tema (MainActivity üçün) qalır.

Paylaşılan `tereqqi` axını `AppViewModel`-də qalır — dörd ekran onu oxuyur, hər
birində yenidən hesablamağın mənası yoxdur. Ekranlar onu parametr kimi yox,
`AppViewModel`-dən `viewModel(…)` ilə alır.

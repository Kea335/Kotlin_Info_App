## Problem

`AppViewModel` (219 sətir) bütün tətbiqin məsuliyyətini daşıyır: aktiv yükləmə,
tənzimləmələr, tərəqqi, kompilyator, axtarış indeksi, meydana kod ötürülməsi.

`AppRoot` kökdə 14 StateFlow toplayır:

```kotlin
val hazir by vm.hazir.collectAsStateWithLifecycle()
val sections by vm.sections.collectAsStateWithLifecycle()
… // 12 dənə də
```

və hamısını parametr kimi ekranlara paylayır. Nəticə: istənilən dəyişiklik
(məsələn bir çalışmanın həll edilməsi) naviqasiya kökünü yenidən qurur, ekranlar
isə müstəqil test edilə bilmir.

## Həll

| ViewModel | Məsuliyyət | Mənbə |
|---|---|---|
| `AppViewModel` | aktiv yükləmə, `hazir`, `yukleneXetasi`, `tereqqi`, meydana ötürülən kod | qalır |
| `LessonsViewModel` | bölmə siyahısı, qruplar, son bölmə, «oxundu» yazılması | yeni |
| `SearchViewModel` | `AxtarisMotoru`, sorğu state-i, nəticələr | yeni |
| `SettingsViewModel` | tema, şrift, tamamlama, sıfırlamalar, rekordlar | yeni |
| `ExerciseViewModel` | T2.2-dən | var |
| `PlaygroundViewModel` | T2.2-dən | var |
| `QuizViewModel` | T2.3-dən | var |

`AppRoot`-dakı `collectAsStateWithLifecycle` çağırışları ekranların özünə keçir;
kökdə yalnız `hazir`, `yukleneXetasi` və tema (MainActivity üçün) qalır.

Paylaşılan `tereqqi` axını `AppViewModel`-də qalır — dörd ekran onu oxuyur, hər
birində yenidən hesablamağın mənası yoxdur. Ekranlar onu parametr kimi yox,
`AppViewModel`-dən `viewModel(…)` ilə alır.

## Tətbiq qeydi (2026-09-17)

Qovluq quruluşu plandakı kimi qurdu (`git mv`, tarixçə qalır):
`ui/lessons`, `ui/exercises`, `ui/quiz`, `ui/playground`, `ui/search`,
`ui/settings`; `ui/screens` silindi. Testlər də eyni paketlərə köçdü.

| ViewModel | Məsuliyyət |
|---|---|
| `AppViewModel` | `hazir`, `yukleneXetasi`, `sections`/`topics` (başlıq və keçidlər), `presets`, `tereqqi`, `hellEdilmis`, `kompilyator`, meydana ötürülən kod |
| `LessonsViewModel` | bölmələr, `qruplar`, `sonBolme`, «oxundu» və «son bölmə» yazısı |
| `SearchViewModel` | `AxtarisMotoru`, `sorgu` (`SavedStateHandle`), `neticeler` |
| `SettingsViewModel` | tema, şrift, tamamlama, rekordlar, sıfırlamalar |
| `QuizViewModel` | + `rekordlar` (rejim kartları üçün) |

`AppViewModel`-dən çıxanlar: tema/şrift/tamamlama axınları və yazıları,
`sonBolme`, `quizRekordlari`, `axtar`/`searchDocs`, `bolmeniOxunmusIsaretle`,
`sonBolmeniYaz`, `calismaniHellIsaretle`, sıfırlamalar. `MainActivity` tema
üçün Activity-yə bağlı `SettingsViewModel` nüsxəsini oxuyur (plandakı
«tema AppViewModel-də qalır» əvəzinə — bir məsuliyyət bir yerdə).

**`AppRoot` 3 state toplayır:** `hazir`, `yukleneXetasi`, `sections`,
`topics` — son ikisi başlıq və `#id` keçidləri üçün. Hər ekran
`viewModel(factory = AppViewModelFactory.Factory)` ilə öz ViewModel-ini
naviqasiya girişindən alır; paylaşılan `tereqqi`/`topics`/`hellEdilmis`
üçün `appVm` parametrlə ötürülür — Activity-yə bağlı nüsxəni `composable {}`
içindən `viewModel()` ilə almaq mümkün deyil (giriş öz ViewModelStore-unu
verir).

**Ekran nümunəsi:** hər ekranda ViewModel-dən oxuyan nazik `XScreen(vm, …)`
və saf `private XContent(...)` var — render məntiqi parametrlə işləyir,
əvvəlki kimi. `BosEkran` `components`-ə çıxdı (dərs və çalışma ekranları
id-ni özləri axtarır).

**Test:** `LessonsViewModelTest` (2), `SearchViewModelTest` (2),
`SettingsViewModelTest` (3); `AppViewModelTest` qalan məsuliyyətlərə görə
yığışdırıldı. Yeni ViewModel testlərində `vm by lazy` — ViewModel
`@Before`-dakı `setMain`-dən sonra yaranmalıdır, əks halda `viewModelScope`
test dispatcher-ini görmür. `./gradlew test` cəmi 188, 0 xəta; lint təmiz;
`assembleDebug` keçir. T1.1 testləri bütün mərhələ boyu yaşıl qaldı.

**Cihazda yoxlanmayıb:** «çalışma həll ediləndə yalnız aid ekran yenidən
qurulur» bəndi recomposition sayğacı tələb edir. Strukturca: `hellEdilmis`
yalnız `ExercisesScreen`, `ExercisePlayerScreen` və `tereqqi` vasitəsilə
oxunur — `AppRoot` onu toplamır.

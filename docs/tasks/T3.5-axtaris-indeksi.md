## Problem

`search.json` (120 KB) `content.json`-dakı mətnin düz variantıdır — eyni
məzmunun ikinci surəti. 15 dildə bu, **15 əlavə fayl** və hər dəfə «indeks
hansı dildəndir?» sualı deməkdir (GPT sənədinin Task 16-sı məhz bunu təklif edir).

Halbuki tətbiqdə `spansToPlain()` funksiyası artıq var (`InlineText.kt:110`) və
heç yerdən çağırılmır. İndeksi yüklənmiş məzmundan qurmaq həm faylı ləğv edir,
həm də «yanlış dilin indeksi» problemini kökündən aradan qaldırır.

## Həll

### 1. İndeksi runtime-da qur

```kotlin
fun indeksQur(sections: List<Section>, dilTeqi: String): AxtarisMotoru {
    val docs = sections.map { s ->
        SearchDoc(
            id = s.id,
            title = s.title,
            group = s.group,
            text = buildString {
                append(s.heading).append(' ').append(s.kicker).append(' ')
                s.blocks.forEach { append(blokMetni(it)).append(' ') }
            }
        )
    }
    return AxtarisMotoru(docs, dilTeqi)
}
```

`blokMetni()` — `verify-content.js`-dəki `bloklardanMetn` funksiyasının Kotlin
qarşılığı: paraqraf (`spansToPlain`), başlıqlar, kod (`title` + `code`),
callout / card / tab daxili blokları, cədvəl hüceyrələri, siyahı, timeline, hero.

Quruluş `Dispatchers.Default`-da, `AppViewModel`-in ikinci yükləmə mərhələsində
(T2.6) — 32 bölmə üçün ~50 ms.

### 2. Dil üzrə normallaşdırma

```kotlin
private fun normallasdir(s: String, dil: String): String = when {
    dil == "az" || dil == "tr" -> s.lowercase(Locale.forLanguageTag(dil))
    dil == "ar" || dil == "fa" -> ereb(s)
    dil == "zh-CN" || dil == "ja" || dil == "ko" -> s.lowercase(Locale.ROOT)
    else -> Normalizer.normalize(s, Normalizer.Form.NFKC).lowercase(Locale.ROOT)
}

/** Ərəb/fars: NFKC + hərəkə və tatvil silinir, ي/ی və ك/ک birləşdirilir. */
private fun ereb(s: String): String =
    Normalizer.normalize(s, Normalizer.Form.NFKC)
        .replace(Regex("[\u064B-\u0652\u0640]"), "")
        .replace('\u064A', '\u06CC')
        .replace('\u0643', '\u06A9')
        .lowercase(Locale.ROOT)
```

**CJK:** çin, yapon və koreya dillərində sözlər boşluqla ayrılmır — tokenizasiya
cəhdi etmə, mövcud `contains` (substring) axtarışı bu dillər üçün onsuz da
düzgün işləyir. Kodda şərhlə qeyd et ki, sonradan «token əlavə edək» deyilməsin.

**Latın dilləri:** NFKC + ROOT lowercase kifayətdir. Diakritik silmə (é → e)
istəyə bağlıdır; əlavə etsən hər iki tərəfə eyni qaydada tətbiq et.

## Diqqət

Axtarış parçası (snippet) **orijinal mətndən** kəsilir, normallaşdırılmışdan
yox — yoxsa istifadəçiyə hərəkəsiz ərəb mətni göstərilər. Mövcud kod bunu
düzgün edir (`doc.text.substring(...)`), pozma.

## Tətbiq qeydi (2026-09-23)

- `data/AxtarisIndeksi.kt` — `axtarisSenedleri(sections)`: `content-lib.js`-dəki
  `axtarisIndeksi`/`bloklardanMetn`-in Kotlin qarşılığı (JS `\s` sinfi də
  daxil — məzmunda qırılmayan boşluqlar var). Silinmədən əvvəl müvəqqəti
  testlə yoxlanıldı: 32 sənədin hamısı `search.json` ilə **bayt-bayt eyni** —
  nəticələr və sıra dəyişmir. `spansToPlain` (UI) yerinə data qatında öz
  `spanMetni` var (`br` → boşluq, JS ilə eyni).
- `SearchViewModel` indeksi `repo.sections()`-dan `Dispatchers.Default`-da
  (testdə ötürülən dispatcher) qurur, `repo.dil` dəyişəndə yenidən. Qurulma
  AppViewModel-in yükləməsinə yox, axtarış ekranına bağlıdır — açılmayanda heç
  qurulmur. `ContentRepository.searchIndex()` və `SearchIndex` modeli silindi,
  `SearchDoc` qaldı.
- `AxtarisMotoru`: normallaşdırma klaster-klaster (əsas simvol + birləşən
  işarələr) aparılır və hər normal simvolun orijinaldakı yeri saxlanılır —
  NFKC genişlənməsi (`ﬁ` → `fi`, `ﷺ` → 18 simvol) və hərəkə silinməsi
  parçanı sürüşdürmür, parça orijinal mətndən (hərəkələrlə) kəsilir. ASCII
  üçün sürətli yol. Ərəb/fars qaydasına tapşırıqdakılardan əlavə `ى` → `ی`
  və `أ/إ/آ` → `ا` birləşdirildi. Diakritik silmə (é → e) edilmədi.
- Alətlər: `build-content.js` və `build-locale.js` `search.json` yazmır,
  köhnəsini silir; `axtarisIndeksi` `content-lib.js`-dən çıxdı.
- Testlər: `AxtarisMotoruTest` +7 (az/tr İ-ı, ərəb hərəkə və tatvil, ərəb
  parçası hərəkəli, CJK substring, alman umlaut və ayrılmış U+0308,
  genişlənən simvolda parça), `SearchViewModelTest` fake bölmələrdən,

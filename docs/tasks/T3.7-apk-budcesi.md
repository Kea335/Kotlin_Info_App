# T3.7 — APK və yaddaş büdcəsi

| | |
|---|---|
| **Prioritet** | P1 |

## Problem

Hazırda aktivlər 840 KB-dır (xam JSON). 15 dil = **≈ 12,6 MB xam mətn**.
APK-da sıxılır (JSON 4–5 dəfə sıxılır, təxminən 2,5–3 MB), amma iki risk var:

1. **Yaddaş.** `ContentRepository` parse olunmuş obyektləri keşdə saxlayır.
   Yalnız seçilmiş dil yüklənməlidir — əks halda dil dəyişdikcə keş böyüyür.
2. **Ölçü.** Hazırkı release APK ≈ 1,9 MB. 15 dil ilə 4–5 MB gözlənilir;
   büdcə qoyulmasa nəzarətsiz artar.

## Addımlar

1. **Keş sıfırlanmasını yoxla** (T3.3-də əlavə olunur). Android Studio Memory
   Profiler: 5 dəfə dil dəyiş → heap dump → `ExerciseTopic` nüsxələrinin sayı
   **25** olmalıdır (50 və ya 125 yox).

2. **CI-da ölçü hesabatı:**

```yaml
- name: APK ölçüsü
  run: |
    ./gradlew assembleRelease
    SIZE=$(stat -c%s app/build/outputs/apk/release/app-release.apk)
    echo "APK: $((SIZE/1024)) KB"
    if [ $SIZE -gt 8388608 ]; then
      echo "::error::APK 8 MB büdcəsini asdi"; exit 1
    fi
```

> Release imzası CI-da yoxdur (keystore repoda deyil) — build imzasız qalır,
> ölçü ölçməsi üçün bu kifayətdir.

3. **Ehtiyat variantlar** (büdcə aşılarsa, sıra ilə):
   - `exercises.json`-u mövzu-mövzu 25 fayla böl → yalnız açılan mövzu yüklənir
     (547 KB → ~22 KB bir mövzu üçün). Ən böyük qazanc budur.
   - Android App Bundle (AAB) + asset pack ilə dil-üzrə paylama
   - Sıxılmış format (ölçüdə qazanc, oxunaqlıqda itki — son çarə)

## Qəbul kriteriyası

- [ ] 15 dil qovluğu ilə release APK ölçüsü ölçülüb və PR-da yazılıb
- [ ] CI ölçü hesabatı işləyir və büdcəni aşanda build-i dayandırır
- [ ] Dil 5 dəfə dəyişdikdən sonra heap-də yalnız bir dilin məzmunu var
- [ ] Büdcə aşılıbsa, seçilən variant qeyd olunub

## Problem

`AppViewModel` bütün asılılıqları özü yaradır:

```kotlin
private val repo = ContentRepository(app)
private val prefs = UserPrefs(app)
val compiler = KotlinCompiler(app)
```

Nəticə: testdə fake vermək mümkün deyil, hər yeni ViewModel eyni obyektləri
təkrar yaradacaq (keşlər ikiləşir), `Context` bütün qatlara sızır.

## Həll

### 1. `KotlinAzApp`

```kotlin
package az.kotlinaz.app

class KotlinAzApp : Application() {
    lateinit var container: AppContainer
        private set

    override fun onCreate() {
        super.onCreate()
        container = AppContainer(this)
    }
}
```

Manifestdə: `<application android:name=".KotlinAzApp" …>`

### 2. `AppContainer`

```kotlin
package az.kotlinaz.app.data

/**
 * Tətbiqin tək asılılıq qrafı. Repozitoriyalar burada bir dəfə yaranır —
 * keşlər (ContentRepository) və DataStore nüsxəsi (UserPrefs) paylaşılır.
 */
class AppContainer(context: Context) {
    private val app = context.applicationContext

    val contentRepository: ContentRepository by lazy { ContentRepository(app) }
    val userPrefs: UserPrefs by lazy { UserPrefs(app) }
    val compilerRepository: CompilerRepository by lazy { RealCompilerRepository(app) }
}
```

> `CompilerRepository` interfeysi T2.2-də yaranır. Bu taskda `KotlinCompiler`-i
> birbaşa saxla, T2.2 onu interfeyslə əvəzləyəcək.

### 3. ViewModel factory

Ortaq köməkçi (`ui/ViewModelFactory.kt`):

```kotlin
val Kontekst: CreationExtras.() -> AppContainer = {
    (this[ViewModelProvider.AndroidViewModelFactory.APPLICATION_KEY] as KotlinAzApp).container
}

object AppViewModelFactory {
    val Factory = viewModelFactory {
        initializer { AppViewModel(Kontekst(), …) }
        // hər ViewModel üçün bir initializer
    }
}
```

Composable-da:

```kotlin
val vm: AppViewModel = viewModel(factory = AppViewModelFactory.Factory)
```

### 4. ViewModel-ləri constructor injection-a keçir

`AppViewModel(app: Application)` → `AppViewModel(repo: ContentRepository, prefs: UserPrefs)`.
`AndroidViewModel` artıq lazım deyil — sadə `ViewModel`-ə keç.

## Diqqət

Hilt **lazım deyil**: tək modullu tətbiqdə üç asılılıq üçün annotasiya emalı
(build vaxtı + öyrənmə xərci) ödəmir. Layihə çoxmodullu olsa yenidən qiymətləndir.

`UserPrefs`-dəki `by preferencesDataStore` genişlənmə xassəsi **fayl səviyyəsində**
qalmalıdır — eyni adla ikinci DataStore yaradılsa çalışma vaxtı istisna atılır.
`AppContainer` onu yalnız bir dəfə çağırır, bu şərt pozulmur.

## Tətbiq qeydi (2026-09-17)

Plan olduğu kimi tətbiq edildi; üç yerdə plandan bir addım irəli gedildi ki,
«testdə fake ötürmək» real olsun, təkcə mümkün yox:

- **`ContentRepository` interfeys oldu**, konkret sinif `AssetContentRepository`.
  ViewModel yalnız interfeysi görür; `AppContainer` konkret sinfi yaradır.
- **`UserPrefs` `Context` yox, `DataStore<Preferences>` alır.** Fayl səviyyəli
  `by preferencesDataStore` delegatı (`Context.kotlinazDataStore`, `internal`)
  yerində qaldı — onu yalnız `AppContainer` bir dəfə oxuyur, «ikinci DataStore»
  şərti pozulmur. Testdə `YaddasDataStore` (yaddaşdakı `MutableStateFlow`
  üzərində) verilir — disk, Robolectric və `Context` lazım deyil.
- **`KotlinCompiler` `Context` görmür:** `internetVar()` `Context` genişlənmə
  funksiyasına çıxarıldı, kompilyatora `sebekeVar: () -> Boolean` lambda kimi
  ötürülür. Əlavə olaraq `io: CoroutineDispatcher` parametri var (defolt
  `Dispatchers.IO`) — testdə test dispatcher-i verilməsə `hazirla()` real IO
  sapına keçir, `hazir` vaxtında `true` olmur və korutin `resetMain()`-dən
  sonra Main-ə qayıdıb çökürdü.

`AppViewModel(repo, prefs, compiler)` — sadə `ViewModel`, `AndroidViewModel`
silindi. Factory: `ui/ViewModelFactory.kt`, `CreationExtras.konteyner`
genişlənməsi `APPLICATION_KEY`-dən `KotlinAzApp.container`-i çıxarır.

**Test:** `ui/AppViewModelTest.kt` — 4 test, fake repository ilə: bölmələr
yüklənir, yüklənmə xətası `hazir`-ı bloklamır, axtarış fake indeks üzərində
işləyir, tənzimləmə yaddaşdakı prefs-ə yazılıb axında görünür.
`./gradlew test` cəmi 151, 0 xəta; lint təmiz; `assembleDebug` keçir.

**Tərəqqi itmir:** DataStore faylının adı (`kotlinaz`) və `Acar` açarları
dəyişmədi — köhnə quraşdırmanın üstünə yenilənəndə eyni fayl oxunur.

T2.2 üçün qeyd: sənəddəki `KotlinCompiler(context)` nümunəsi köhnədir —
konstruktor artıq `(prefs, sebekeVar, io)`-dur.

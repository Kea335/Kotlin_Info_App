## Problem

Kompilyator birbaşa Composable-dan çağırılır:

```kotlin
// ExercisePlayerScreen.kt:460, PlaygroundScreen.kt:201
scope.launch {                       // rememberCoroutineScope()
    veziyyet = when (val r = compiler.isle(kod.value.text)) { … }
}
```

Üç nəticəsi var:

1. **Sorğu kompozisiyaya bağlıdır.** İstifadəçi «Yoxla» basıb ekrandan çıxsa
   (geri, başqa tab), 3–10 saniyəlik sorğu səssizcə ləğv olur — qayıdanda nə
   nəticə var, nə xəta.
2. **Test mümkün deyil.** Yoxlama məntiqi (normallaşdırma + müqayisə + «həll
   edildi» yazılması) UI ağacının içindədir.
3. **`vm.compiler` UI-ya açıq sahədir** — repository sərhədi yoxdur.

### 2. `PlaygroundViewModel`

```kotlin
class PlaygroundViewModel(
    private val compiler: CompilerRepository,
    private val state: SavedStateHandle
) : ViewModel() {

    var kod: String
        get() = state["kod"] ?: BOS_KOD
        set(v) { state["kod"] = v }

    private val _ui = MutableStateFlow<MeydanVeziyyeti>(MeydanVeziyyeti.Bos)
    val ui: StateFlow<MeydanVeziyyeti> = _ui.asStateFlow()

    fun isle() {
        if (_ui.value is MeydanVeziyyeti.Isleyir) return
        _ui.value = MeydanVeziyyeti.Isleyir
        viewModelScope.launch { _ui.value = neticeyeCevir(compiler.isle(kod)) }
    }
}
```

### 4. UI-nı sadələşdir

Composable yalnız `ui` state-ini render edir və event göndərir
(`vm.isle()`, `vm.kodDeyisdi(it)`, `vm.sifirla()`). `AppViewModel.compiler`
sahəsi silinir; `AppRoot`-dan `compiler = vm.compiler` ötürmələri götürülür.

Redaktorun performans qaydası pozulmamalıdır: `KodRedaktoru` `MutableState`
qəbul edir ki, hər vuruşda yalnız redaktor yenidən qurulsun. ViewModel-ə
keçəndə ya `mutableStateOf`-u ViewModel-də saxla, ya da `SavedStateHandle`-ın
`getMutableStateFlow`-undan `collectAsState` ilə oxu və yazını debounce et.
Ən sadə variant: ViewModel-də `var kodState by mutableStateOf(TextFieldValue(...))`
+ `SavedStateHandle`-a yalnız mətn (String) yazmaq.

## Problem

Kompilyator birbaşa Composable-dan çağırılır:

```kotlin
// ExercisePlayerScreen.kt:460, PlaygroundScreen.kt:201
scope.launch {                       // rememberCoroutineScope()
    veziyyet = when (val r = compiler.isle(kod.value.text)) { … }
}
```

Üç nəticəsi var:

1. **Sorğu kompozisiyaya bağlıdır.** İstifadəçi «Yoxla» basıb ekrandan çıxsa
   (geri, başqa tab), 3–10 saniyəlik sorğu səssizcə ləğv olur — qayıdanda nə
   nəticə var, nə xəta.
2. **Test mümkün deyil.** Yoxlama məntiqi (normallaşdırma + müqayisə + «həll
   edildi» yazılması) UI ağacının içindədir.
3. **`vm.compiler` UI-ya açıq sahədir** — repository sərhədi yoxdur.

### 2. `PlaygroundViewModel`

```kotlin
class PlaygroundViewModel(
    private val compiler: CompilerRepository,
    private val state: SavedStateHandle
) : ViewModel() {

    var kod: String
        get() = state["kod"] ?: BOS_KOD
        set(v) { state["kod"] = v }

    private val _ui = MutableStateFlow<MeydanVeziyyeti>(MeydanVeziyyeti.Bos)
    val ui: StateFlow<MeydanVeziyyeti> = _ui.asStateFlow()

    fun isle() {
        if (_ui.value is MeydanVeziyyeti.Isleyir) return
        _ui.value = MeydanVeziyyeti.Isleyir
        viewModelScope.launch { _ui.value = neticeyeCevir(compiler.isle(kod)) }
    }
}
```

### 4. UI-nı sadələşdir

Composable yalnız `ui` state-ini render edir və event göndərir
(`vm.isle()`, `vm.kodDeyisdi(it)`, `vm.sifirla()`). `AppViewModel.compiler`
sahəsi silinir; `AppRoot`-dan `compiler = vm.compiler` ötürmələri götürülür.

Redaktorun performans qaydası pozulmamalıdır: `KodRedaktoru` `MutableState`
qəbul edir ki, hər vuruşda yalnız redaktor yenidən qurulsun. ViewModel-ə
keçəndə ya `mutableStateOf`-u ViewModel-də saxla, ya da `SavedStateHandle`-ın
`getMutableStateFlow`-undan `collectAsState` ilə oxu və yazını debounce et.
Ən sadə variant: ViewModel-də `var kodState by mutableStateOf(TextFieldValue(...))`
+ `SavedStateHandle`-a yalnız mətn (String) yazmaq.

## Tətbiq qeydi (2026-09-17)

**Repository sərhədi.** `data/CompilerRepository.kt` — `veziyyet`, `hazirla()`,
`isle()`. Ayrıca `RealCompilerRepository` sinfi yaradılmadı: T2.1-dən sonra
`KotlinCompiler` onsuz da `Context` görmür, ona görə interfeysi birbaşa o
tətbiq edir. `AppContainer.compiler` artıq `CompilerRepository` tipindədir;
`AppViewModel` onu `private` saxlayır və yalnız `kompilyator: StateFlow<KompilyatorVeziyyeti>`
açır (Meydan zolağı və Tənzimləmələr üçün). UI-da `KotlinCompiler` istinadı qalmayıb.

**`PlaygroundViewModel`** (`ui/PlaygroundViewModel.kt`) — `MeydanVeziyyeti`
bura köçdü (public). `kod: MutableState<TextFieldValue>` ViewModel-dədir və
olduğu kimi `KodRedaktoru`-ya verilir — redaktorun performans qaydası
dəyişmir. `isle()` `viewModelScope`-da işləyir, `Isleyir` halında ikinci
çağırış heçdir. Seçili preset `SavedStateHandle`-dadır.

**`ExerciseViewModel`** (`ui/ExerciseViewModel.kt`) — `YoxlamaVeziyyeti` və
`Rejim` bura köçdü. `SavedStateHandle`-da: rejim, səviyyə, indeks, ipucu/həll/
cavab-sorğusu bayraqları, cari çalışma id-si. `calismaniAc(calisma)` çalışma
dəyişəndə kodu və paneli sıfırlayır, eyni çalışmada (döndərmə, geri) heç nəyə
toxunmur — Composable onu `remember(calisma.id)` içindən çağırır. `yoxla()`
düzgün nəticədə `prefs.calismaniHellIsaretle` yazır; nəzəri düzgün cavab və
oflayn «Həll etdim» də `hellIsaretle()` ilə ViewModel-dən keçir.
`onHellIsaretle` parametri ekrandan götürüldü.

**Redaktor mətni və `SavedStateHandle`.** Hər vuruşda yazmaq əvəzinə
`state.setSavedStateProvider(KOD) { savedState { putString(METN, kod.value.text) } }`
— mətn yalnız sistem vəziyyəti saxlayanda oxunur; bərpa `state.get<SavedState>(KOD)`
ilə. Debounce lazım olmadı.

**Naviqasiya bağlılığı.** Hər iki ViewModel `composable {}` içində
`viewModel(factory = AppViewModelFactory.Factory)` ilə yaradılır, yəni
`NavBackStackEntry`-yə bağlıdır: mövzu başına bir `ExerciseViewModel`, geri
qayıdanda eyni nüsxə (və gedən sorğu) qalır. Factory `createSavedStateHandle()`
ilə girişin arqumentlərini və saxlanmış vəziyyətini gətirir.

**Test.** `test/data/FakeCompilerRepository.kt` — verilən `RunResult`-ı
qaytarır, göndərilən kodları saxlayır, `CompletableDeferred` ilə «icra
gedərkən» halını dondura bilir. `PlaygroundViewModelTest` (7) və
`ExerciseViewModelTest` (13): altı `RunResult` halı, «həll edildi» yazısı
(uyğun → yazılır, uyğunsuz/xəta/oflayn → yazılmır), kilid (ikinci çağırış
serverə getmir), çalışma dəyişməsi, cavab axını, indeks sıfırlanması.
`./gradlew test` cəmi 171, 0 xəta; lint təmiz; `assembleDebug` keçir.

**Cihazda yoxlanmayıb:** «yazı zamanı yalnız redaktor yenidən qurulur» bəndi
Layout Inspector tələb edir, sessiyada cihaz yox idi. Struktur eynidir —
`kod.value` kompozisiyada oxunmur, yalnız «Kopyala» lambdasında; ViewModel
`MutableState`-i olduğu kimi ötürür. Ekrandan çıxıb qayıdanda nəticənin
görünməsi testlə (nəticə UI-sız gəlir) və `viewModelScope` ilə təmin olunur,
əl ilə cihazda yoxlanmalıdır.

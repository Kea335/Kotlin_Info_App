## Problem

Naviqasiya string route-larla qurulub (`AppRoot.kt:290–302`):

```kotlin
const val DERS = "ders/{id}"
fun ders(id: String) = "ders/$id"
```

və arqumentlər `entry.arguments?.getString("id").orEmpty()` ilə oxunur.
Səhv açar adı və ya çatışmayan arqument yalnız çalışma vaxtında üzə çıxır.
Layihədə `kotlinx.serialization` onsuz da var, Navigation Compose 2.9 isə
tip-təhlükəsiz route-ları dəstəkləyir.

## Həll

```kotlin
// ui/Yollar.kt
@Serializable object Dersler
@Serializable data class Ders(val id: String)
@Serializable object Calismalar
@Serializable data class Calisma(val id: String)
@Serializable object Quiz
@Serializable object Meydan
@Serializable object Axtaris
@Serializable object Tenzimleme
```

```kotlin
NavHost(nav, startDestination = Dersler) {
    composable<Dersler> { … }
    composable<Ders> { entry ->
        val yol: Ders = entry.toRoute()
        …
    }
}

nav.navigate(Ders(id = bolme.id))
```

Alt menyunun seçili elementi və başlıq seçimi `currentBackStackEntry`-dən
`destination.hasRoute<Dersler>()` ilə müəyyən edilir — `cariYol` string
müqayisələri silinir.

`basliqUcun()` funksiyası da route tipinə görə `when`-ə keçir; T3.4-dən sonra
başlıqlar `stringResource` ilə gələcək, ona görə funksiyanı Composable et.

## Qəbul kriteriyası

- [x] Kodda naviqasiya üçün string literal qalmayıb
- [x] Bütün keçidlər (dərs, çalışma, quiz, meydan, axtarış, tənzimləmə) işləyir
- [x] Alt menyu seçili elementi düzgün işarələnir
- [x] `saveState`/`restoreState` davranışı qalır (tab sürüşmə mövqeyi)
- [x] `launchSingleTop` davranışı qalır (axtarış ikonuna təkrar toxunuş yığın yaratmır)
- [x] Daxili keçidlər (`#null-safety`) işləyir

## Diqqət

Bu task **davranış dəyişmir** və digərlərini bloklamır — vaxt darsa Sprint 5-ə
keçirilə bilər. Faydası: T3.4-də başlıqları resources-a çıxaranda route
müqayisələri təmiz qalır.

## Tətbiq qeydi

- `ui/Yollar.kt`: `Yol` obyekti — hər ekran `@Serializable object`/`data class`.
- `AppRoot.kt`: `composable<Yol.Ders>` + `entry.toRoute<Yol.Ders>().id`;
  `nav.navigate(Yol.Ders(id))`. `cariYol` string müqayisələri silindi —
  alt menyu elementi və «geri» düyməsi `destination.hasRoute<T>()` ilə seçilir.
- `basliqUcun()` Composable oldu və `NavBackStackEntry` alır; id-ni route-dan
  tipli oxuyur (`arguments?.getString("id")` yoxdur).
- `popUpTo(Yol.Dersler) { saveState = true }`, `launchSingleTop`, `restoreState`
  olduğu kimi qaldı — davranış dəyişmir.
- ViewModel-lər route arqumentini `SavedStateHandle`-dan oxumur (id ekran
  parametridir), ona görə serialization açar adı dəyişikliyi onlara toxunmadı.

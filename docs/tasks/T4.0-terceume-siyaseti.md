## Məqsəd

Tərcümə başlamazdan **əvvəl** qaydaları yazmaq. Hər tərcümə tapşırığı bu iki
fayl ilə başlayacaq; AI tərcüməsində onlar prompt-un məcburi hissəsidir.

## 1. `localization/glossary.json`

```json
{
  "terms": {
    "Null Safety":          { "az": "Null təhlükəsizliyi", "tr": "Null güvenliği", "en": "Null safety", "ru": "Null-безопасность" },
    "Coroutine":            { "az": "Coroutine", "tr": "Coroutine", "ru": "Корутина" },
    "Recomposition":        { "az": "Yenidən qurulma", "en": "Recomposition" }
  },
  "doNotTranslate": [
    "Kotlin", "Java", "Android", "JetBrains", "Compose", "Gradle",
    "ViewModel", "Composable", "Flow", "StateFlow", "MutableList",
    "val", "var", "fun", "when", "suspend", "data class", "sealed"

```

Daxil edilməli əsas terminlər: Null Safety, Coroutine, Flow, StateFlow,
MutableList, Inheritance, Encapsulation, Polymorphism, Dependency Injection,
ViewModel, Composable, Recomposition, Extension function, Higher-order function,
Lambda, Scope function, Delegate, Generic, Type inference, Immutability.

Hər termin üçün 15 dildə **təsdiqlənmiş** qarşılıq; tərcüməçi öz variantını
uydurmamalıdır.

## 2. `localization/POLICY.md`

Məcburi qaydalar:

### Tərcümə OLUNMUR
- Kotlin açar sözləri: `fun`, `val`, `var`, `class`, `when`, `if`, `for`, `suspend`…
- Stdlib / API / framework adları: `listOf`, `StateFlow`, `Activity`, `Composable`
- Sinif, funksiya, dəyişən **identifikatorları** kod nümunələrində
- Sabit ID-lər: bölmə, blok, çalışma, quiz, preset
- Cavab indeksi (`a`) və variantların **sırası**
- `level`, `index`, `special`, `sectionId` və digər texniki sahələr

### Tərcümə OLUNUR
- Tapşırıq mətni, ipucu, izah, sual, variantların **mətni**
- Başlıq, alt başlıq, kicker, callout başlığı, kart başlığı, tab etiketi
- Kod bloklarının **başlığı** (`title`), kodun özü yox
- Kod içindəki **şərhlər** (`// İstifadəçinin yaşını yoxlayırıq`)
- UI sətirləri (`strings.xml`)

### String literal-lar — əsas qayda

Kod içindəki mətn literal-ları **defolt olaraq dəyişmir**:

```kotlin
// AZ və EN variantında eyni qalır:
println("Salam, Kotlin!")
```

Səbəb: `gozlenilen` nəticə, `hell` (model həll) və `starter` bir-birindən
asılıdır. Literal dəyişsə üçü də eyni anda dəyişməlidir — 625 çalışma × 14 dil
= 8 750 sinxronlaşma nöqtəsi. Bu riski **sıfırlayırıq**.

İstisna: dərsin məqsədi məhz mətnlə işləməkdirsə (məsələn `uppercase()`
nümunəsi), çalışmaya bayraq qoyulur:

```json
{ "id": "metnler-p-07", "localizedIo": true }
```

Belə çalışmalarda `starter`, `hell` və `gozlenilen` **birlikdə** tərcümə olunur,
validator isə üçünün də overlay-də olmasını tələb edir.

### Rəqəmlər və formatlar
- Kod nümunələrində Avropa rəqəmləri (5, 10) — ərəb/fars daxil
- Mətndə tarix/say formatı dilin öz qaydası ilə
- `%1$d`, `%2$s` nişanları **olduğu kimi** qalır, sırası dəyişə bilər

## 3. AI tərcümə prompt şablonu

`localization/PROMPT.md` — hazır şablon:

```
Sən KotlinAZ öyrənmə tətbiqi üçün <DİL> tərcüməçisisən.
Aşağıdakı POLICY və GLOSSARY qaydalarına tam əməl et.
Sənə JSON overlay parçası verilir; YALNIZ dəyərləri tərcümə et, açarlara toxunma.
Kod bloklarında yalnız şərhləri tərcümə et.
Variantların sırasını dəyişmə.
<POLICY mətni>
<GLOSSARY parçası>
<JSON parçası>
```

## 4. Validator inteqrasiyası

`validate-locales.js`-ə glossary yoxlaması:
- Qadağan siyahısındakı söz tərcümə olunubsa xəbərdarlıq
  (məsələn `ViewModel` → «Görünüş modeli»)
- Glossary-də təsdiqlənmiş qarşılıq varsa, fərqli variant işlədilibsə xəbərdarlıq

## Qəbul kriteriyası

- [x] `glossary.json` ≥ 20 termin × 15 dil (az/en/tr/ru insan təsdiqi gözləyir)
- [x] `POLICY.md` yuxarıdakı bütün bölmələri əhatə edir
- [x] `PROMPT.md` hazırdır və bir dildə sınaqdan keçirilib (en)
- [x] Validator glossary qaydalarını yoxlayır
- [x] `localizedIo` bayrağı modeldə və validatorda dəstəklənir

## Diqqət

Glossary-ni **bir nəfər** təsdiqləməlidir. 15 dildə qarşılıqları AI ilə
yaratmaq olar, amma az/tr/en/ru üçün insan baxışı vacibdir — bu dördü digər
tərcümələrin pivotu olacaq.

## Tətbiq qeydi

**Kod yarpaqları.** Spesifikasiya «kodun özü tərcümə olunmur» deyir, amma
şərhlərin tərcüməsini tələb edir. Ona görə kod bloku, `starter`, `hell` və
meydan nümunəsi **yalnız şərhi olduqda** overlay yarpağıdır
(`tools/kod-serhleri.js`): kod leksik hissələrə bölünür, şərhlər nişanla
əvəzlənir və bazanın «skeleti» ilə müqayisə olunur. Skelet fərqlidirsə
validator xəta verir, `build-locale` bazanı saxlayır, tamamlanma faizi
sahəni saymır. Testlər: `node tools/test-kod-serhleri.js` (CI-da).

**`localizedIo` modeldə deyil, ayrı fayldadır** —
`localization/localizedIo.json` (`{"calismalar": {"<id>": "<səbəb>"}}`).
Səbəb: `exercises.json` saytdan yenidən qurulur, bayraq orada itərdi. Hələ
heç bir çalışma işarələnməyib — fayl olmayanda siyahı boşdur; ilk namizədlər
T4.1-də `metnler` mövzusundan seçiləcək.

**Lüğət formatı** spesifikasiyadakı nümunədən fərqlənir: açar slug-dur
(`null-safety`), hər dildə əsas forma, `_formalar[dil]` isə validatorun qəbul
etdiyi əlavə formalardır (hal şəkilçili kök, ingiliscə ad) — aqqlütinativ
dillərdə (az, tr) alt sətir müqayisəsi əks halda yanlış xəbərdarlıq verir.
`doNotTranslate`-dən adi mətndə yalnız xüsusi adlar və çoxsözlü terminlər
yoxlanılır: `var`, `when` azərbaycanca mətndə adi söz ola bilər.

**Sınaq** — `localization/PROMPT.md`-in sonunda: en, 17 sahə, xəta 0;
qəsdən pozulmuş kod və tərcümə olunmuş ad tutuldu.

**Qalan iş.** Lüğətin az/en/tr/ru qarşılıqlarını insan təsdiqləməlidir
(`glossary.json` → `_meta.tesdiq`). Lüğət yoxlaması real terminlə ilk dəfə
T4.1-də işə düşəcək.
